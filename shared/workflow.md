# 统一执行工作流（规范 v1）

Python 与 C++ 必须遵循相同的阶段次序和阶段结果语义。内部函数名称、并发策略和容器类型可以不同。

```text
CLI / 环境校验
      ↓
发现 QQ 进程与 wrapper.node
      ↓
建立 QQ 账号 ↔ 进程实例映射
      ↓
选择目标账号和数据库目录
      ↓
发现数据库并读取第一页元数据 / salt
      ↓
处理全局数据库固定密钥候选
      ↓
扫描目标进程并收集候选密钥
      ↓
用数据库第一页 HMAC 验证候选
      ↓
保存版本化 key_map.json
      ↓
等待 QQ 退出（或显式跳过）
      ↓
重新发现并重新读取数据库
      ↓
按稳定 salt 将密钥映射到最新数据库文件
      ↓
逐个解密、验证并写入输出目录
      ↓
输出汇总并返回稳定退出码
```

## 阶段定义

### 0. 参数和环境校验

- 解析 CLI 参数，验证 QQ 号、PID、路径和语言。
- 非 Windows 环境或必要 API 不可用时按错误码表退出。
- 解析并创建输出根目录；不能把输入数据库目录误当作输出目录。

### 1. 进程发现与实例映射

- 发现当前运行的 QQ 进程及对应 `wrapper.node`。
- 优先使用打开的 `nt_msg.db` 文件句柄路径建立账号映射，不得依赖进程枚举顺序猜测账号。
- 若自动映射存在歧义，不得静默选择任意实例。
- 用户显式指定 `--pid` 时允许诊断覆盖，但必须在账号映射不一致或未确认时发出警告。

### 2. 数据库目录发现

- 未指定 `--db-dir` 时，根据已识别的账号数据库路径发现账号库及适用的全局库。
- 指定 `--db-dir` 时，该目录作为账号库目录；按 CLI 契约不额外推导全局库。
- 只把满足预期 SQLite/SQLCipher 文件头和最小长度要求的数据库纳入后续处理。
- 无可用数据库时按 `DATABASE_NOT_FOUND` 退出。

### 3. 密钥候选与验证

- 全局库按现有固定密钥逻辑处理；账号库按数据库 salt 收集候选。
- 所有候选必须通过对应数据库第一页 HMAC 验证，才可被认定为已恢复密钥。
- 相同 salt 的候选应去重；不能仅因内存扫描发现字符串就写入结果。
- 未验证的候选不得写入 JSON、日志或临时文件。

### 4. 写入 key map

- 至少有一个已验证密钥才生成 `key_map.json`。
- 新文件必须符合 [key-map.schema.json](key-map.schema.json)，采用 `schema_version: 1`。
- `_generated` 必须使用 UTC 时间和 `Z` 后缀。
- 写入采用临时文件完成后原子替换；成功提示只能在落盘成功后输出。

### 5. WAL 刷新等待

- 默认提示用户关闭 QQ，并等待相关 QQ 进程退出；用户按 Enter 可显式选择不等待，但必须显示数据可能未完成 WAL checkpoint 的警告。
- `--no-wait` 直接跳过等待，也必须显示同一性质的警告。
- 若进程已经退出则直接继续。
- 该阶段的目的在于尽可能使用已经 checkpoint 的数据库文件，不应宣称按 Enter 或 `--no-wait` 能保证数据库处于一致状态。

### 6. 重新发现数据库

- 等待结束后重新枚举数据库文件并重新读取第一页。
- 以 salt 与已验证的密钥映射重新关联数据库文件；不能只依赖扫描前的旧文件列表。
- 若数据库消失、salt 无法匹配或文件无法读取，将该文件标记为未处理，并在最终摘要中说明。

### 7. 解密与验证

- 每个源数据库对应唯一目标路径；目标文件名冲突时不得静默覆盖。
- 先写入临时文件，验证其可由 SQLite 打开并能读取系统表；验证成功后再替换最终文件。
- 验证失败时删除临时文件，保留先前已存在的有效输出。
- 只有验证成功的文件计入 `OK`；失败文件计入 `FAIL`。

### 8. 汇总与退出

- 汇总已验证密钥数、待处理数据库数、解密成功数和失败数。
- 所有计划文件成功返回 `0`；有一个或多个解密/验证失败返回 `22`。
- 不存在已验证密钥返回 `20`；不能持久化 key map 返回 `21`。
- 警告不应被误报为成功，也不应覆盖更具体的失败错误码。

## 一致性要求

- Python 和 C++ 的阶段次序一致。
- 一个阶段失败时，两边在相同前置条件下应归入相同错误分类。
- 同一输入和环境下，两边默认输出根目录、JSON schema、目标文件命名策略一致。
- 文案允许不同语言；阶段结果、错误 ID 和退出码不允许因语言改变。
