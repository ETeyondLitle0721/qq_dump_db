# 进程退出码与错误分类（规范 v1）

退出码是供脚本、自动化任务和用户判断结果的稳定接口。文案可以翻译，错误码和退出码不得随语言变化。

| 退出码 | 稳定错误 ID | 含义 | 典型情况 |
|---:|---|---|---|
| `0` | `OK` | 全部计划内处理成功 | 成功生成密钥映射，且所有匹配数据库均解密并通过验证。 |
| `2` | `CLI_USAGE` | 命令行参数错误 | 缺少 `--qq`、未知参数、非法 PID、无效语言或参数缺值。 |
| `10` | `PLATFORM_UNSUPPORTED` | 平台或运行环境不支持 | 非 Windows，或必要系统 API 不可用。 |
| `11` | `QQ_PROCESS_NOT_FOUND` | 未找到目标 QQ 进程 | 没有可用 QQ.exe / wrapper.node 进程，且未提供有效的显式 PID。 |
| `12` | `INSTANCE_MAPPING_FAILED` | 账号与进程无法可靠关联 | 句柄映射失败、目标账号没有唯一映射、映射歧义。 |
| `13` | `DATABASE_NOT_FOUND` | 数据库目录或数据库文件不可用 | `--db-dir` 不存在、账号目录无法发现、没有符合格式的数据库。 |
| `20` | `KEY_NOT_RECOVERED` | 没有恢复到经验证的密钥 | 没有候选密钥通过数据库第一页 HMAC 验证。 |
| `21` | `OUTPUT_IO_FAILED` | 输出目录或密钥 JSON 写入失败 | 权限不足、磁盘错误、JSON 临时文件无法替换。 |
| `22` | `DECRYPT_FAILED` | 一个或多个数据库解密或验证失败 | 部分解密失败、SQLite 验证失败、重新发现后无法匹配数据库。 |
| `70` | `INTERNAL_ERROR` | 未预期的内部错误 | 未归类异常；日志中应记录错误 ID，不得记录密钥原文。 |
| `130` | `INTERRUPTED` | 用户中断 | Ctrl+C 或控制台中断。 |

## 判定规则

1. 参数校验优先于任何进程或文件访问；帮助和版本请求直接返回 `0`。
2. 没有任何经 HMAC 验证的密钥时返回 `20`，不生成空 `key_map` 文件。
3. 已有密钥但 JSON 无法持久化时返回 `21`；不得继续声称结果已保存。
4. 只要计划解密的数据库中有一个失败，最终返回 `22`；所有计划文件均成功时返回 `0`。
5. 进程访问被拒绝、个别进程无法读取等可恢复情况先作为警告；若最终因此无法获得任何已验证密钥，返回 `20`。
6. 错误消息写入标准错误流；普通进度和成功摘要写入标准输出流。
7. 对外显示稳定错误 ID（例如 `INSTANCE_MAPPING_FAILED`），而不是要求调用者解析本地化自然语言。
8. 退出码 `70` 只用于未预期异常，不应用它替代已定义错误。

## 日志与敏感信息

- 不输出完整密钥、完整候选 key blob 或 `key_map` JSON 内容。
- PID、数据库文件名、盐值可用于诊断，但默认不打印用户聊天内容或数据库记录。
- 对异常输出应避免包含密钥、内存片段或其他敏感缓冲区内容。
