# 跨语言契约测试清单

本清单用于第二阶段及之后验收，不意味着本阶段已经运行过这些测试。

## CLI

- [ ] 两端都要求 `--qq`，且都拒绝空值、非数字账号值。
- [ ] 两端都接受相同的 `--pid`、`--db-dir`、`-o/--output` 参数。
- [ ] 两端都实现 `--output-dir`、`--lang`、`--no-wait`、`--help`、`--version`。
- [ ] 对未知参数、缺失参数值、非法 PID 和不支持语言返回相同错误分类及退出码。
- [ ] 相对输出目录统一以当前工作目录为基准；相对 `--output` 统一以输出根目录为基准。

## JSON

- [ ] 两端新生成的 JSON 均通过 `key-map.schema.json` 验证。
- [ ] `schema_version` 恒为整数 `1`。
- [ ] salt 为 32 位小写十六进制，key 为 64 位小写十六进制。
- [ ] `_generated` 是以 `Z` 结尾的 UTC RFC 3339 时间。
- [ ] 两端均能读取 legacy v0 文件，但不再生成 legacy v0。
- [ ] 没有任何已验证密钥时，不生成空 key map 文件。

## 工作流

- [ ] 两端都先验证候选密钥，再写入 key map。
- [ ] 默认都等待 QQ 退出，并在等待后重新发现数据库。
- [ ] `--no-wait` 和按 Enter 提前继续均明确警告 WAL 风险。
- [ ] 两端都按重新读取后的数据库 salt 重新匹配 key。
- [ ] 解密失败不留下半成品覆盖最终输出。
- [ ] 目标文件名冲突时两端均拒绝静默覆盖。

## 退出码

- [ ] 同一类 CLI 错误在两端返回 `2`。
- [ ] 未发现进程、映射失败、数据库缺失、无密钥、输出失败、解密失败分别映射到规范退出码。
- [ ] 成功且无解密失败时返回 `0`。
- [ ] 任一计划数据库解密/验证失败时返回 `22`。

## 国际化

- [ ] 中文、英文和日文切换只影响用户可见文案，不影响参数、JSON 字段、错误 ID 和退出码。
- [ ] 未翻译文案按 `zh-CN` 回退，再回退到消息 ID。
- [ ] 中文目录参数和中文控制台输出可正确处理。
